# Geek Season — frontend

Клиентская часть платформы подготовки к ЕГЭ по информатике. Работает с API
[backend](https://github.com/Geek-Season/backend).

**Стек:** React 18, Vite 6, React Router 6, TanStack Query 5 (кэш запросов), qrcode.react.

## Страницы

| Адрес | Страница |
|---|---|
| `/` | Главная: приветствие по времени суток и случайная фраза, счётчик «До ЕГЭ — N дней» (дату задаёт админ), анимация из символов; гостю — о сайте и вход |
| `/tasks` | Сетка номеров ЕГЭ с поиском и прогрессом |
| `/tasks/:code` | Задачи номера: фильтры по источнику и прогрессу, сортировка, проверка ответа; для 19–21 — три поля ответа |
| `/login` | Вход через Telegram: QR-код или код из бота |
| `/profile` | Ранг, календарь активности за год (как в LeetCode, с текущей и лучшей серией), что повторить, последние ответы, достижения |
| `/exam` | Пробник: таймер, автосохранение ответов, навигация по позициям |
| `/exam/:id` | Результат: первичный и тестовый балл, разбор |
| `/rating` | Таблица лидеров по PTS: всё время, эта неделя (прирост), по номеру ЕГЭ (`?board=week`, `?board=number&number=27`); фильтр по рангу (`&rank=legend`), «Immortal #N», своя строка ниже топа; клик по строке — карточка ученика (`?user=12`): ранг, место, решено, серия, достижения, календарь активности |
| `/admin` | Админка (роль admin; вход — из меню под аватаркой). Вкладки: «Задачи» — редактор банка (Markdown с предпросмотром, ответ, картинки и файлы); `?tab=users` — ученики: поиск, карточка (`&user=id`) с PTS, рангом, калибровкой, ником, аватаркой, датой регистрации, ролью, блокировкой и сбросом статистики; `?tab=log` — журнал действий админов; `?tab=site` — дата ЕГЭ для счётчика на главной |

## Запуск

Требуется Node.js 20+ и запущенный backend на `http://127.0.0.1:8000`.

```bash
npm install
npm run dev       # http://127.0.0.1:5173
npm run build     # сборка в dist/
```

Запросы к `/api/*` проксируются на backend (`vite.config.js`); адрес backend задаётся переменной `BACKEND_URL`.

## Текст задач в Markdown

Условие, вопросы 19–21 и разборы пишутся в Markdown (`components/Markdown.jsx`, react-markdown):

| Пишем | Получаем |
|---|---|
| `**жирный**`, `*курсив*`, `~~зачёркнутый~~` | **жирный**, *курсив*, ~~зачёркнутый~~ |
| `<u>подчёркнутый</u>`, `<mark>маркер</mark>` | подчёркивание, выделение |
| `1111011<sub>2</sub>`, `2<sup>10</sup>` | индексы и степени |
| `$27x98876_{22}$`, `$$\sum_{i=1}^n i$$` | формулы (KaTeX — грузится только для задач с формулами) |
| таблицы, списки, `` `код` ``, блоки кода | как в GitHub |
| `![](/files/….png)` | картинка в этом месте текста |

- Одиночный перенос строки — новая строка: старые задачи из простого текста выглядят как раньше.
- Сырой HTML не исполняется: теги `<u> <sub> <sup> <mark> <s> <br>` распознаёт свой плагин (`components/markdownTags.js`), любой другой HTML показывается как текст.
- В редакторе — панель кнопок, Ctrl+B/I/U, предпросмотр рядом, вставка картинок в текст (кнопка 🖼, Ctrl+V, перетаскивание). Новые картинки до сохранения стоят в тексте как `![](pending:…)` и после загрузки заменяются на адрес.
- Картинки, вставленные в текст, не повторяются под условием; картинку, вставленную только в разбор, сервер не показывает ученику до ответа.

## Кэш запросов

Ответы API хранятся в памяти (TanStack Query, `src/queries.js`), поэтому повторный переход на страницу
показывает данные сразу, без «Загрузка…» и без запроса.

| Данные | Свежие | Особенности |
|---|---|---|
| Номера, задачи номера | 1 мин | Задачи номера грузятся заранее при наведении на карточку; список не перезапрашивается при возврате во вкладку |
| Статистика профиля | 1 мин | После ответа на задачу помечается устаревшей и обновляется в фоне |
| Достижения | 15 с | Их выдаёт фоновый воркер через 1–2 с после ответа |
| Рейтинг | 30 с | Каждая таблица (вкладка, номер, ранг) кэшируется отдельно |
| Идущий пробник | не кэшируется | Ответы и время меняются постоянно |
| Завершённый пробник | навсегда | Не меняется; результат кладётся в кэш сразу после «Завершить» |

- **Ключи содержат id ученика** — данные одного никогда не покажутся другому; при выходе кэш очищается.
- **После ответа на задачу** метка «Решена» и «решено X из Y» обновляются на месте, профиль и рейтинг — помечаются устаревшими.
- **После правок в редакторе** списки номеров и задач устаревают у всех страниц.
- **401 на запрос с токеном** (токен истёк) — сайт выходит из аккаунта, а не делает вид, что ученик вошёл.

## Деплой на GitHub Pages

Сайт собирается и выкладывается сам при каждом изменении `main` (`.github/workflows/deploy.yml`)
и открывается по адресу <https://geek-season.github.io/frontend/>.

Один раз настроить в репозитории на GitHub:

1. **Settings → Pages → Build and deployment → Source:** GitHub Actions.
2. **Settings → Secrets and variables → Actions → Variables → New repository variable:**
   `API_URL` = адрес backend на Netrun, например `https://neyman-inf.netrun.io` (без `/` в конце).
3. На backend в секретах Netrun: `CORS_ORIGINS=https://geek-season.github.io` — иначе браузер
   не пустит сайт к API.
4. **Actions → Deploy to GitHub Pages → Run workflow** (или любой push в `main`).

Поменялся адрес API — измени `API_URL` и снова нажми **Run workflow**.

| Переменная сборки | Что задаёт |
|---|---|
| `VITE_API_URL` | Адрес API. Не задан — `/api` (прокси Vite при разработке) |
| `VITE_BASE` | Путь сайта. На Pages — `/frontend/`, локально — `/` |

Проверить сборку как на Pages: `VITE_API_URL=http://127.0.0.1:8000 VITE_BASE=/frontend/ npm run build:pages`.
GitHub Pages умеет только отдавать файлы, поэтому `npm run build:pages` (`scripts/pages-routes.mjs`) кладёт
копию `index.html` в папку каждой известной страницы — `rating/`, `exam/`, `login/`, `profile/`, `admin/`,
`tasks/1/` … `tasks/27/`. Сайт держит в адресе слэш на конце (`/frontend/rating/`), и F5 на этих страницах
получает настоящую страницу со статусом 200. Для остальных адресов (результат пробника `/exam/12`)
GitHub Pages отдаёт `404.html` — ту же копию, страница открывается, но со статусом 404.

## Структура

```
src/
├── main.jsx            маршруты
├── api.js              все запросы к backend
├── queries.js          кэш запросов: ключи, сколько данные свежие, что обновить после изменений
├── queryClient.js      настройки кэша
├── auth.jsx            контекст авторизации, токен в localStorage
├── styles.css          стили и цветовые переменные
├── components/         Layout, TaskCard, TaskMedia (картинки и файлы), ActivityChart,
│                       Markdown (показ текста задачи), MarkdownEditor (редактор с панелью кнопок)
└── pages/              страницы приложения
```
